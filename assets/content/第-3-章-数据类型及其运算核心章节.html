第 3 章　数据类型及其运算（核心章节）

本章是整门课的第一重难点。所有编程题、实验题都绕不开"常量/变量怎么定义、类型怎么转、算出来对不对"。

高频考点3.1 C 标识符的命名规则

硬性语法规则（违反即编译错误）：

  1. 只能由字母 (A-Z, a-z)、数字 (0-9)、下划线 _ 组成；
  2. 不能以数字开头（1abc 非法，_abc、a1 合法）；
  3. 区分大小写：num 与 Num 是两个完全不同的标识符；
  4. 不能使用 C 关键字（int、if、for、return、unsigned 等）。

命名风格约定（不影响语法，但影响可读性）：

类型 风格 示例
变量 小写单词 / 驼峰 sum、maxValue
符号常量 全大写 PI、MAX
函数 动词开头 getMax()、printLine()

易错点 易错点 2：附录 D 经典案例——

C
int main() {
    int a = 5;
    x = 10;              // ❌ x 未定义 → 编译错误
    printf("%d %d", A, x); // ❌ A 未定义（且大小写混用）
}
编译器把 a 和 A 视为两个不同的变量。

类别 写法示例 实际类型
整数常量 100 int
长整数常量 1000L / 1000l long
长长整数常量 1000LL long long
无符号常量 1000U unsigned int

单精度实型 3.14F float
长双精度实型 3.14L long double

高频考点 易错点 3：1.2333*10^4^ 不是常量，^ 在 C 中是按位异或运算符！ 科学计数法的正确写法是 1.2333e4（或 1.2333E4），结果为 12333。

C
printf("%f\n", 1.2333e4);   // 输出 12333.000000 ✔
printf("%f\n", 1.2333*10^4^); // 编译报错（4 是整型，无法按位异或）✘

3.2.2 字符常量

C
char ch = 'A';      // 单引号 + 单个字符
printf("%c", ch);   // A
printf("%d", ch);   // 65  ← 字符以 ASCII 码形式存储

易错点 易错点 4： - 'x' 是字符（单引号），"x" 是字符串（双引号）； - '0' 的 ASCII 是 48，与数字 0（值为 0）完全不同； - char 不能存中文（一个汉字在 UTF-8 下占 3 字节，超出 char 的表示范围）——这是"char 不能用中文"的原理； - 转义字符 '\' 要写成 '\\'；字符 '\0' 是字符串结束符，值为 0。

3.2.3 字符串常量

本质：字符数组。

C
char str[4] = "aaa";
/* 实际存储： 'a'  'a'  'a'  '\0'  共 4 字节 */

易错点 易错点 5：字符串常量自动携带结尾的 '\0'（一个字节，值为 0）。 所以 "aaa" 占 4 个字节，数组长度至少写 4；"hello" 需要 char s[6]。 教材第 4 次实验原文：「由于字符串包含结束标记字符，所以通常设计定义字符数组大小的时候，应该设计比实际可能存放字符数量 +1 个空间」。

高频考点3.4 有符号 / 无符号

3.4.1 基本概念

关键字 含义 可存范围
signed（默认） 有符号 正数、负数、0
unsigned 无符号 仅 ≥ 0（多出 1 位，最高位不用做符号位）

平时写 int 就等价于 signed int。

3.4.2 什么时候用 unsigned

  1. 数据不可能为负：长度、个数、索引、内存地址、像素颜色、端口值；
  2. 需要更大的正数范围：同样字节数，无符号能存更大的正数。
C
unsigned int len = strlen("hello");   // 长度不可能是负数

重难点高频考点3.4.3 混用比较的"大坑"

规则：有符号数与无符号数一起运算时，有符号数会自动转成无符号数。

C
#include <stdio.h>
int main(){
    int a = -1;
    unsigned int b = 2;
    if (a < b) {
        printf("a < b\n");
    } else {
        printf("a >= b\n");     /* 实际输出这一行！ */
    }
    return 0;
}

原理：a 转为 unsigned 后，-1 变成 4294967295，远大于 2。

易错点 这是命题/改错题的头号考点。破解办法：把比较双方转成同一类型再比，或改用 long。 辨析延伸 教材特别强调：unsigned 只能与 int / char 连用（不能写 unsigned double）。

高频考点3.5 字符类型与 ASCII

  • char 可以存放 ASCII 码表中的所有字符（标准 ASCII 为 0~127，扩展到 255）。
  • 字符以整数形式在内存中存储，因此字符可以参与算术运算。
C
char c1 = 'a', c2, c3;
c2 = c1 + 3;    // 'd'  （'a'=97, +3=100='d'）
c3 = c1 - 32;   // 'A'  （97-32=65='A'）← 大小写转换的原理

必须背下来的 ASCII 值 高频考点：

字符 ASCII 记忆法
'0' 48 数字连续：'0'~'9' = 48~57
'A' 65 大写连续：'A'~'Z' = 65~90
'a' 97 小写连续：'a'~'z' = 97~122

辨析延伸 推导技巧（实验要求掌握）：记住 '0'=48 和 'A'=65，其他一律加减推出。 例如 '5' = 48+5 = 53；'B' = 65+1 = 66；'c' = 97+2 = 99。 大小写关系：小写 = 大写 + 32。

分类函数（ctype.h，比手写 if 更规范，教材 lt05-06.c 有对比）：

C
#include <ctype.h>
if (isdigit(c)) ...      // '0'~'9'
if (isalpha(c)) ...      // 字母
if (isupper(c)) ...      // 大写
if (islower(c)) ...      // 小写
if (isspace(c)) ...      // 空白符
if (iscntrl(c)) ...      // 控制字符
tolower(c); toupper(c);  // 转换

高频考点3.6 浮点型

3.6.1 三种浮点类型

类型 字节 有效数字 后缀 输出
float 4 6~7 位 F/f %f
double 8 15~17 位 无（默认） %f
long double 8/16 18~19 位 L/l %Lf

高频考点 命题点：题目未说明精度时，默认用 double。 printf("%f", 356); 会输出 0.000000，因为 356 是整型，%f 按浮点解读它的位模式（教材 lt03-08.c 明确演示）。

重难点高频考点3.6.2 精度误差：不能直接 ==

C
double a = 0.1;
double b = 0.2;
double c = a + b;
printf("0.1 + 0.2 = %.20f\n", c);
// 输出：0.1 + 0.2 = 0.30000000000000004441
if (c == 0.3) { ... }   // ❌ 条件为假

原理：计算机用二进制存储浮点数，十进制小数 0.1、0.2 无法被二进制精确表示，存的是近似值；相加后产生微小偏差。

C
printf("%.20f\n", 10.0/3.0);
// 输出：3.33333333333333348136

正确做法：用绝对值阈值判断

C
#include <stdio.h>
#include <math.h>      // fabs() 在此
#define EPSILON 1e-9

int main() {
    double x = 0.0;
    if (fabs(x) < EPSILON) {          // ✔
        printf("x接近0\n");
    }
    return 0;
}

函数与阈值必须按精度配套：

类型 绝对值函数 机器 epsilon 建议阈值
float fabsf() ≈1.19×10⁻⁷ 1e-6
double fabs() ≈2.22×10⁻¹⁶ 1e-9 ~ 1e-12
long double fabsl() — 1e-18

辨析延伸 编译时需要链接数学库：GCC 下 gcc program.c -o program -lm。

易错点 易错点 7（补充）：浮点除以 0 不会像整数那样报编译警告，而是产生特殊值： - 正无穷 1.#INF（float）/ inf（double） - 负无穷 -1.#INF / -inf - 0/0 或 sqrt(-1) → -1.#IND / nan（非数） 而整数除 0 编译器会直接给 warning: division by zero [-Wdiv-by-zero]。

3.6.3 浮点数的其他表示形式

形式 示例 说明
十进制 356.0 最常用
指数形式 123456.789e5 等于 12345678848.0
十六进制浮点 0x1.8p+3 C99，p 后是 2 的幂
C
float a = 123456.789e5;
printf("%f\n", a);   // 12345678848.000000

高频考点 陷阱：float 只有 6~7 位有效数字，123456.789e5 超出有效位数，打印时会丢精度， 出现 12345678848.000000 这种"少了几位"的结果——这不是 printf 的 bug，是 float 本身只有 32 位。

高频考点3.6.4 舍入规则：四舍六入五成双

C 的 %.nf 采用银行家舍入（round-half-to-even），与数学"逢 5 进位"不同：

需约位数字 后续情况 处理
≤ 4 — 舍去，不进位
≥ 6 — 进位
= 5 后面无有效数字 前一位是偶数 → 舍去；前一位是奇数 → 进位
= 5 后面有有效数字 只要不为 0 就进位

辨析延伸 例（均已实机验证）：2.5 → 2（2 是偶数）；3.5 → 4（3 是奇数）；0.5 → 0；1.5 → 2；4.5 → 4。

高频考点 注意"后面有有效数字就进位"这条规则的坑：它说的是十进制书写的直觉，实际取决于该数在二进制中的真实值。 比如 2.675 在二进制里是 2.67499999999999982236，比 2.675 略小，所以 %.2f 输出的是 2.67 而不是 2.68。 同理 1.005 → 1.00、0.125 → 0.12（0.125 可精确表示，2 是偶数故舍）。

高频考点3.7 sizeof 运算符

C
int a = 2;
printf("%zu\n", sizeof(int));   // 4
printf("%zu\n", sizeof(a));     // 4  ← 与 sizeof(int) 等价
printf("%zu\n", sizeof(long));  // 4 (Windows) / 8 (Linux 64位)

高频考点 格式符必记： | 返回/类型 | 格式符 | |---|---| | unsigned int | %u | | signed int | %d | | size_t（sizeof、strlen 的返回值） | %zu |

❌ 常见错误：printf("%d", sizeof(int)); —— 64 位系统上 size_t 是 8 字节而 int 是 4 字节，参数不匹配，行为未定义。 教材原例用的是 printf("%d",sizeof(i))，在现代 64 位编译器上应写 %zu。

重难点高频考点3.8 数据类型转换

重难点3.8.1 隐式转换（自动转换）

基本规则：

  1. 同类型运算 → 结果仍为原类型；
  2. 不同类型运算 → 自动转换为值域更大（占字节更多）的类型。

转换方向（按字节数从小到大）：

TXT
char (1)  →  short (2)  →  int (4)  →  long (4/8)  →  long long (8)
                                    ↘  float (4)  →  double (8)  →  long double
运算场景 结果类型 例子
int + int int 1 + 2
int + long long 教材 lt03-07.c：x+a 中 x 是 long → 结果 long
int + double double 10 / 3.0 = 3.3333…
int + float float
double + float double
int / int int 10 / 3 = 3（截断）

高频考点 高频判断题：10 / 3 的值是 3，10 / 3.0 的值是 3.3333…。 只要 / 的任意一边是浮点数，就执行浮点除法，保留小数部分。

3.8.2 强制转换（显式转换）

C
float a = 3.14;
int b = (int)a;         // 3  ← 直接截断小数，不是四舍五入！
int c = (int)(a * 100); // 314 ← 先算再转，等价于 (int)(a*100)

易错点 易错点 8：(int)3.99 = 3，不是 4。强制转换是截断。 想要四舍五入：(int)(x + 0.5)（仅适用于正数）。

易错点 易错点 9（长整型截断）（格式类型符 PPT slide 1）：

C
int a = 40000;
short s;
s = a;                 // C 规则：长整型赋值给更短整型 → 直接截断，取低位
printf("a = %d\n", a);  // 40000
printf("s = %hd\n", s); // 40000 mod 65536 = 40000，但作为 short 解释为 -25536
补码存储：a = 40000 = 0x9C40，取低 16 位仍是 0x9C40； 但 0x9C40 最高位为 1，按 16 位补码解释 = 40000 - 65536 = -25536。

高频考点3.8.3 同一内存、不同格式符解读（格式类型符 PPT slide 3）

C
int a = 100;
printf("%d\n", a);   // 100        ← 按 int 补码规则解读
printf("%f\n", a);   // 0.000000   ← 按 IEEE754 单精度解读同一批 32 bit
  • int 存储：纯补码 00000000 00000000 00000000 01100100
  • %f 解读：拆成 1 符号位 + 8 阶码 + 23 尾数 → 算出一个完全无关的小数 （实测：0x00000064 按单精度解读约为 1.4e-43，用 %f 打印显示 0.000000）

高频考点 不报错的错：编译器不会因为格式符不匹配而报错（老式编译器只给警告）， 但运行结果完全错误。这是"能编译但结果不对"的经典来源。

高频考点3.8.4 scanf 读取 double 的"内存错位"（格式类型符 PPT slide 4）

C
double b;
scanf("%f", &b);   // ❌ %f 往 4 字节 float 槽写，double 是 8 字节 → 数据错乱
scanf("%lf", &b);  // ✔ double 必须用 %lf
  • %f → float，4 字节：1 符号位 + 8 阶码 + 23 尾数
  • %lf → double，8 字节：1 符号位 + 11 阶码 + 52 尾数

教材 lt03-08.c 的对照演示正是这个知识点。

重难点3.9 运算符与表达式

3.9.1 算术运算符

运算符 名称 说明
+ - 加、减 二元（双目）
* 乘 不可省略（不能写成 2x）
/ 除 两边都是 int → 整数除法；任一为浮点 → 浮点除法
% 取余（求模） 只能用于整数，且除数不能为 0

高频考点 取余的符号规则：余数的正负跟第一个操作数（左操作数）保持一致。

C
10 % 3    //  1
-10 % 3   // -1   ← 负号跟左边
10 % -3   //  1   ← 负号跟左边
-10 % -3  // -1
口诀：左边是正就是正，左边是负就是负。

易错点 易错点 10：% 用于浮点数是语法错误。教材附录 D 案例：

C
float a, b;
printf("%d", a % b);   // ❌ 编译错误：' %' 操作数类型不匹配

高频考点3.9.2 自增自减 ++ / --

写法 含义
++a 先加后用：a 的值先 +1，再参与运算
a++ 先用后加：先用 a 的当前值参与运算，再让 a +1
--a 先减后用
a-- 先用后减
C
int i = 8;
printf("%d %d %d %d\n", ++i, --i, i++, i--);

高频考点 注意：这一行在标准 C 中属于未定义行为（多个自增自减作用于同一变量且无序列点）， 输出结果依编译器而异。GCC 16 实测输出为 8 8 7 8。 教材用它来演示"编译器求值顺序"，不要背这个输出。

真正需要掌握的是单个运算符的语义（已实机验证）：

表达式 表达式自身的值 变量最终值
++i（i=8） 9 9
i++（i=8） 8 9
--i（i=8） 7 7
i--（i=8） 8 7

口诀：前置是"改完再用"，后置是"用完再改"。

高频考点 自增自减作为独立语句：i++; 和 ++i; 效果完全相同（都是 i 加 1）。 区别只在与其他表达式混合时出现。

易错点 易错点 11：++ 和 -- 只能作用于变量，不能作用于常量或表达式：

C
5++;          // ❌ error C2105: '++' needs l-value
(a+b)++;     // ❌ 同上

高频考点 经典"坑"（教材 lt08-30.c）：

C
int i = 2, p;
p = fun(i, ++i);   // ⚠️ 传参顺序未定义，行为取决于编译器！
C 标准不规定函数实参的求值顺序（左到右还是右到左由编译器决定）， 所以 fun(i, ++i) 的结果不可移植。考试遇到这类题要看教材给的编译器约定。

高频考点 赋值与逻辑运算符的优先级（教材 lt05-02.c 考的正是这个）：

C
printf("%d,%d\n", i==5 && c && (j=8), x+y||i+j+k);
赋值运算符 = 的优先级低于 &&，也低于 ||（从高到低：&& → || → ?: → =）。 本题中 (j=8) 已用括号括起，优先级不影响解析，真正决定结果的是 && 的短路： i==5 为假 → 整个 && 短路 → (j=8) 根本不执行，j 保持原值 2。 第二个表达式 x+y||i+j+k：|| 左侧 x+y 非 0 → 短路 → 结果为 1。 实测输出：0,1。

3.9.3 关系运算符

运算符 含义
== 等于
!= 不等于
> < 大于 / 小于
>= <= 大于等于 / 小于等于

易错点 易错点 12（头号错误）：= 是赋值，== 是比较。

C
if (a = 3)  ...   // ❌ 永远为真（把 3 赋给 a，非 0 即真）
if (a == 3) ...   // ✔

高频考点 关系表达式永远只有 0 或 1：a > b 的值是 1(真) 或 0(假)。

高频考点 连续比较陷阱（教材 lt05-02.c）：

C
printf("%d,%d\n", 1<j<5, x-5.25<=x+y);
// 1<j<5  等价于  (1<j) < 5  →  (1) < 5  →  1  （不是"1到5之间"！）

高频考点 教材原题：printf("%d,%d\n", k==j==i+5); 解析：k==j → 3==2 → 0；0 == (i+5) → 0 == 6 → 0。

高频考点3.9.4 逻辑运算符

运算符 名称 规则
! 非 真→假，假→真
&& 与 两边都为真才真
|| 或 有一边为真就真

短路求值（short-circuit） 高频考点高频考点：

表达式 求值顺序 效果
a && b 先 a，若 a 为假不求 b 保护：p != NULL && *p > 0
a || b 先 a，若 a 为真不求 b 保护：i < n && a[i] == v

高频考点 教材重点：短路是考点也是实用技巧，可避免无意义的除法/数组越界。

C
if (n != 0 && 100 / n > 10) { ... }   // ✔ n==0 时不会执行除法
if (n != 0 || 100 / n > 10) { ... }   // ❌ n!=0 为真时短路，反而不会算除法——写反了

高频考点 ! 的返回值：!x 的结果恒为 0 或 1。

C
printf("%d,%d\n", !x*!y, !!!x);   // x=3e+5(真), y=0.85(真)
// !x=0, !y=0 → 0*0 = 0
// !!!x = !(!(!x)) = !(!0) = !1 = 0

高频考点 逻辑运算符的返回值不一定是 0/1（C 标准的真实行为）： a || b 若 a 为真，返回的是 a 的值；a && b 若 a 为假，返回 a 的值。 但在 if 条件中，任何非 0 都当真，所以实践中等价于 0/1。

重难点3.11 补码与有符号 / 无符号解读（实验五 · 核心考点）

🧩 来源：实验「进制转化补码」。同一串二进制，解读规则不同，数值完全不同——这是本实验的核心考点。

前提：

类型 位宽 范围 内存含义
char（有符号） 8 位 -128 ~ +127 存补码；bit7 是符号位（0 正 1 负）
unsigned char 8 位 0 ~ 255 直接存真值二进制，没有补码概念，所有位都是数值位

三条关键规则：

  1. 正数：原码 = 反码 = 补码，机内直接存真值；
  2. 负数：补码 = 对应正数原码 → 按位取反 → +1；例外：8 位下 10000000 专门规定代表 -128（它没有原码、反码，不能从原码推）；
  3. %o / %x 只读取内存里的比特串按无符号数转八 / 十六进制，不关心变量有没有符号。

完整实验示例：

C
char a = -128;          /* 机内 10000000 */
printf("%d %o %x\n", a, a, a);
unsigned char d = 255;  /* 机内 11111111 */
printf("%d %o %x\n", d, d, d);
变量 机内比特串 %d 解读 %o %x
char a = 89 01011001 89 131 59
char b = -128 10000000 -128（补码规定） 200 80
unsigned char c = 89 01011001 89（与 a 完全相同） 131 59
unsigned char d = 255 11111111 255（无符号直接加权） 377 ff
若 signed char 存 11111111 同上 -1！（补码解读） 377 ff

⚠️ 整型提升陷阱：char b = -128 直接传给 printf 时 b 先提升为 4 字节 int，符号位扩展后是 0xFFFFFF80，所以某些编译器下 %o 输出 37777777600、%x 输出 ffffff80——本质就是 8 位补码 10000000 提升成 32 位后的样子。同一串 bit，两套解读，数值天差地别。
