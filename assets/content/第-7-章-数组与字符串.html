易错点7.1.2 易错点 25：数组长度必须是常量表达式

C
int n;scanf("%d", &n);int a[n];      // ❌ 编译错误（C89/C99 中 VLA 除外）—— 数组大小不能动态定义

附录 D 原文：「数组名后用方括号括起来的是常量表达式，可以包括常量和符号常量。即 C 不允许对数组的大小作动态定义。」 （C99 起支持变长数组 VLA，但不是所有编译器都支持，考试按不支持处理。）

正确做法：

C
#define N 100int a[N];

7.1.3 元素访问与地址

C
int a[10];for (i = 0; i < 10; i++) a[i] = i;      // 下标法for (i = 0; i < 10; i++) *(a+i) = i;    // 指针法（完全等价）​printf("%p\n", a);        // 数组首地址printf("%p\n", &a[0]);    // 与 a 相同printf("%p\n", &a);       // ⚠️ 与 a 数值相同但类型不同（&a 是 int(*)[10]）

高频考点 a 和 &a[0] 数值相同（都是首元素地址），但 &a 的类型是"指向整个数组的指针"。

辨析延伸 遍历数组长度的推荐宏（教材 lt07-05.c）：

⚠️ 只能用于真正的数组，不能用于指针（指针的 sizeof 是 8，公式失效）。

易错点7.1.4 易错点 26：数组越界

C 语言不检查数组越界——这是 C 的最大安全隐患之一。

C
int a[5] = {1,2,3,4,5};printf("%d\n", a[10]);   // 编译通过！运行时读越界内存 → 乱码或崩溃

辨析延伸 防御手段：使用前检查 if (i >= 0 && i < n)。

VLA 还有几条限制，选择题常拿它们做干扰项：

高频考点7.1.6 段错误（Segmentation fault）绝大多数是下标越界

程序运行时突然打印一行 Segmentation fault（Windows 上是「已停止工作」或返回码 -1073741819），九成以上不是编译器坏了，而是访问了不属于自己的内存。数组越界是最常见的一种。

本质 C 语言不做数组边界检查：a[5] 只是「从 a 的地址往后数 5 个 int」，编译器不会拦你。写进去的值可能覆盖别的变量、函数的返回地址，甚至踩到只读页。

下面这段有 bug，但未必崩溃——这正是越界最坑的地方：

Coob-sum.c
#include <stdio.h>​int main(void){    int a[5] = {1, 2, 3, 4, 5};    int i, sum = 0;​    for (i = 0; i <= 5; i++)     /* ❌ i == 5 时访问 a[5]，已经越界 */        sum += a[i];    printf("sum=%d\n", sum);    return 0;}

多跑一次循环，读到的是数组后面那块内存里的垃圾值：结果可能只是偏大，也可能直接崩，甚至「今天没事、明天崩」，完全取决于内存布局。

越界的典型形态，按出现频率排：

写法问题正确做法
for (i = 0; i <= n; i++)多跑一次，访问 a[n]i < n
把 a[n] 当最后一个元素最后一个元素是 a[n-1]最大下标 = 长度 − 1
char s[5]; strcpy(s, "hello");没有空间放 '\0'目标数组至少 6 字节，或用 strncpy
char s[10]; scanf("%s", s);输入超过 9 个字符就溢出scanf("%9s", s) 或 fgets
字符串忘了补 '\0'printf("%s") 一路读到越界复制完手动 dst[i] = '\0'
二维数组 a[3][4] 用 a[i][j] 时 j 到 4行内越界，会串到下一行j < 4

区分 段错误不只有越界一个来源：空指针解引用（int *p = NULL; *p = 1;）、野指针（未初始化就使用）、改写字符串字面量（char *s = "abc"; s[0] = 'x';）同样会崩。做题时看到「程序崩溃」，先查这三类。

排查越界最实用的三招：

  1. 把长度算对：n = sizeof(a) / sizeof(a[0])，别手写数字；
  2. 循环边界打印出来：在循环里临时 printf("%d %d\n", i, n);，一眼看出多跑的那次；
  3. 上机时用检查工具：gcc -fsanitize=address -g x.c 编译，越界会直接指出第几行、越了几个字节（考试不用，但调程序很快）。

高频考点7.3.6 为什么 scanf 读不到带空格的句子

输入 hello world，程序只打印出 hello——这不是 bug，是 %s 的规定动作。

规则 scanf("%s", s) 的执行过程是：跳过前导空白 → 连续读取非空白字符 → 遇到空格、制表符、换行立刻停止，并在末尾补 '\0'。所以它本质上只能读「一个单词」。

输入方式遇到空格能否读整行越界保护

gets(s)继续读✔无，C11 已删除，不要用
fgets(s, n, stdin)继续读✔（含行尾 \n）有，最多读 n−1 个字符
getchar() 循环继续读✔要靠自己判断边界

如果只是想读「一个不含空格的单词」，但担心输入太长把数组写爆，就给格式串加宽度限制——这个数字是最多写入的字符数，不含结尾的 '\0'：

C
char s[10];scanf("%9s", s);        /* 最多写 9 个字符 + 1 个 '\0'，刚好放满 */

缓冲区溢出 char s[10]; scanf("%s", s); 时输入 30 个字符，多出来的会写到数组后面，轻则改坏相邻变量，重则 Segmentation fault。这是「越界」在字符串上最常见的样子。

另一个高频坑：%c 不跳过空白。先用 scanf("%d") 读数字，再用 %c 读字符，读到的是上一行残留的换行符：

Cscanf-char-bug.c
#include <stdio.h>​int main(void){    int n;    char c;​    scanf("%d", &n);        /* 输入 5 之后按回车，'\n' 留在缓冲区 */    scanf("%c", &c);        /* 这里读到的其实是 '\n'，不是想要的字符 */    printf("n=%d c=[%c]\n", n, c);    return 0;}

两种改法都行：在格式串前面加一个空格（" %c"，表示先吃掉所有空白），或者在两次输入之间加一句 getchar();。

手写 strcpy 是教材和考试的经典题，核心就是「复制到 '\0' 为止，并且把 '\0' 也复制过去」：

C
/* 版本一：数组下标，最容易看懂，也最适合写在卷面上 */char *my_strcpy(char *dst, const char *src){    int i = 0;​    while (src[i] != '\0')    {        dst[i] = src[i];        i++;    }    dst[i] = '\0';          /* ⚠️ 千万别漏，否则 dst 不是字符串 */    return dst;}
C
/* 版本二：指针写法，等价且更短（考试也常见） */char *my_strcpy(char *dst, const char *src){    char *p = dst;​    while ((*dst++ = *src++) != '\0')        ;    return p;}

三个必踩的坑

  1. 目标数组不够大：char s[5]; strcpy(s, "hello"); —— 5 个字符加 '\0' 需要 6 字节，越界。
  2. 目标是字符串字面量：char *s = "abc"; strcpy(s, "xy"); —— 字面量在只读段，运行直接 Segmentation fault。要复制就必须用数组。
  3. 用 strncpy 忘了补结束符：strncpy(dst, src, 3) 在 src 长度 ≥ 3 时只写 3 个字符，不补 '\0'，后面一 printf 就越界。

安全一点的复制写法：

Csafe-copy.c
#include <stdio.h>#include <string.h>​/* 最多复制 size-1 个字符，并保证结果一定以 '\0' 结尾 */char *safe_copy(char *dst, const char *src, int size){    if (size <= 0) return dst;    strncpy(dst, src, size - 1);    dst[size - 1] = '\0';       /* 手动收尾，专治 strncpy 不补 '\0' */    return dst;}​int main(void){    char buf[8];​    safe_copy(buf, "C Primer Plus", sizeof buf);    printf("[%s] len=%u\n", buf, (unsigned)strlen(buf));    return 0;}

高频考点7.4 排序算法

7.4.1 选择排序（教材 lt07-04.c / lt07-20.c）

TXT
思想：第 i 轮从 a[i..n-1] 中找出最小（或最大）的元素，与 a[i] 交换。      第 i 轮结束后，a[i] 就是第 i 个（或倒数第 i 个）元素就位。
C
for (i = 0; i < n-1; i++) {    p = i;  q = a[i];              /* 假设 a[i] 最小 */    for (j = i+1; j < n; j++)        if (q < a[j]) { p = j; q = a[j]; }    if (p != i) { s = a[i]; a[i] = a[p]; a[p] = s; }   /* 必须判断 p != i */}
  • 比较次数：固定为 n(n-1)/2；
  • 移动次数：最多 n-1 次；
  • ⚠️ 教材特别提醒：「p 不等于 i 需要交换」——若 p == i 仍交换，会把元素换到自己，逻辑上没错但多余。

7.4.2 冒泡排序（教材 lt07-24.c）

TXT
思想：相邻两元素比较，若逆序就交换。每一趟把当前最大（或最小）的元素"冒"到末尾。
C
for (j = 0; j <= N-2; j++)             /* 共 N-1 趟 */    for (i = 0; i <= N-j-2; i++)       /* 每趟比较次数递减 */        if (a[i] > a[i+1]) { t = a[i]; a[i] = a[i+1]; a[i+1] = t; }

高频考点 为什么要 N-j-2？ 第 j 趟结束后，末尾已有 j 个元素就位，不必再比较。 i 的上限是 N-j-2，保证 a[i+1] 不越界（最大时 i+1 = N-j-1 ≤ N-1）。 内层次数减少 → 总次数为 n(n-1)/2，比"固定比较"更优。

#include <stdio.h>​int main()​{    // 1.定义一个二维数组​    int arr[3][5] =​    {        {1,2,3,4,5},​        {11,22,33,44,55},​        {111,222,333,444,555}    };​    // 2.利用索引的方式进行遍历​    // arr[0]:表示二维数组当中的第一个一维数组, {1,2,3,4,5}​    // arr[1]:表示二维数组当中的第二个一维数组, {11,22,33,44,55}​    // arr[2]:表示二维数组当中的第三个一维数组, {111,222,333,444,555}​    for (int i = 0; i < 3; i++)​    {        // i:依次表示二维数组中的索引​        for (int j = 0; j < 5; j++)​        {            // j:依次表示一维数组中的索引​            // 内循环: 遍历每一个一维数组​            printf("%d ", arr[i][j]);        }​        // 当内循环结束之后，表示一维数组遍历完毕了​        printf("\n");    }​    return 0;}

输出 stdout

11 22 33 44 55 
111 222 333 444 555

辨析延伸 要点 二维数组是「一维数组的数组」：arr[i] 是第 i 个一维数组，arr[i][j] 再取其中元素。
